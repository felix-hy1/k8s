## 学习目标

## 12.1 调度器怎么选节点

```
Predicates(过滤):资源够不够?端口冲突?亲和/反亲和?污点不容忍?volume 拓扑?
      ↓ 剩下可行节点
Priority(打分):资源均衡度、镜像已存在、亲和性偏好……
      ↓ 最高分
绑定(Bind):把 nodeName 写进 PodSpec
```

只调度一次:已绑定节点的 Pod(哪怕节点后来不行了)不会被主动迁移,除非用 Descheduler 之类工具。

## 12.2 控制手段一览

| 手段 | 语义 | 强弱 |
|------|------|------|
| nodeSelector | 节点标签硬匹配 | 硬(不满足就 Pending) |
| nodeAffinity requiredDuringScheduling... | 节点亲和(必满足) | 硬 |
| nodeAffinity preferredDuringScheduling... | 节点偏好(尽量) | 软 |
| podAffinity / podAntiAffinity | 与其他 Pod 同居/分居 | 有硬有软 |
| tolerations + taints | 节点"驱离"默认 Pod,Pod"豁免" | 节点侧控制 |
| topologySpreadConstraints | 按拓扑域(节点/zone)均匀分布 | 硬或软 |

> 完整语义提示:亲和性字段名都是 `...DuringSchedulingIgnoredDuringExecution`——只在调度时生效,已运行的 Pod 不动。

## 实验列表

### 实验 1:节点标签 + nodeSelector / nodeAffinity

```bash
cd /mnt/d/k8s/12-调度机制/manifests
# 给两个 worker 打不同标签(模拟不同规格机器)
kubectl label node k8s-learning-worker disktype=ssd
kubectl label node k8s-learning-worker2 disktype=hdd
kubectl get nodes -L disktype

kubectl apply -f lab01-nodeaffinity.yaml
kubectl get pods -n sched-lab -o wide
# ns-pod 落在 ssd;affinity-pod 落在 ssd;
# no-fit-pod 要 nvme → 没有 → Pending
```

### 实验 2:Pod 亲和与反亲和

```bash
kubectl apply -f lab02-pod-affinity.yaml
kubectl get pods -n sched-lab -o wide --show-labels
# with-cache:通过 podAffinity 贴着 cache Pod 同节点
# spread-web:podAntiAffinity 硬约束 → 每节点最多 1 副本(注意:3 副本恰好 3 节点才调度得开)
```

### 实验 3:污点与容忍

```bash
# 给 worker2 打污点:普通 Pod 将不再调度到它
kubectl taint node k8s-learning-worker2 team=ml:NoSchedule
kubectl apply -f lab03-taints-tolerations.yaml
kubectl get pods -n sched-lab -o wide
# normal-pod → 落 worker(或控制面)
# tolerant-pod → 带容忍,可以落 worker2
# 观察控制面本身:为什么系统 Pod 能在控制面跑?它们都容忍了 control-plane 污点
kubectl taint node k8s-learning-worker2 team=ml-     # 删除污点(注意结尾的 -)
```

### 实验 4:拓扑打散(高可用布局)

```bash
kubectl apply -f lab04-topology-spread.yaml
kubectl get pods -n sched-lab -o wide | grep spread
# maxSkew: 1 → 各节点副本数差值不超过 1
```

### 手动运维:cordon / drain(README 演示)

```bash
kubectl cordon k8s-learning-worker     # 禁止新 Pod 调度(SchedulingDisabled)
kubectl drain k8s-learning-worker --ignore-daemonsets --delete-emptydir-data   # 驱离 workload(运维节点前必做)
kubectl uncordon k8s-learning-worker   # 恢复
```


## 常见问题

| 问题 | 答案 |
|------|------|
| Pod 一直 Pending 怎么查? | `kubectl describe pod xx | tail -10` 的 Events 会写明过滤原因 |
| 污点三种 effect 区别? | NoSchedule(不调度新的)/ PreferNoSchedule(尽量)/ NoExecute(还要驱逐已有的) |
| podAntiAffinity 用 required 会不会自锁? | 会:节点数 < 副本数时必然有 Pod 调度不上;生产常用 preferred + PDB |
| 删除污点的语法? | `kubectl taint node <n> key=value:Effect-`(最后减号) |
