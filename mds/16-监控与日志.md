# 第 16 章 监控与日志(可观测性)

> 📁 本章实验资源(yaml / 脚本 / sql)位于 `D:\k8s\16-监控与日志\`,本文档位于 `D:\k8s\mds\`。

## 学习目标

1. 搭建 kube-prometheus-stack:Prometheus + Grafana + Alertmanager 一条龙
2. 认识 Prometheus Operator 的核心概念(ServiceMonitor/PrometheusRule)
3. 掌握 K8s 日志体系:logs 命令、日志落盘位置、采集方案选型

## 16.1 可观测性三支柱

| 支柱 | 回答的问题 | K8s 生态常用 |
|------|------------|--------------|
| Metrics(指标) | 系统现在什么状态? | Prometheus + Grafana |
| Logging(日志) | 具体发生了什么? | kubectl logs → Loki/ELK |
| Tracing(链路) | 请求经过了哪里? | Jaeger/Tempo(本手册不展开) |

## 16.2 Prometheus 体系速览

```
exporter(暴露 /metrics) ←抓取─ Prometheus(时序库+告警评估) ──► Grafana(可视化)
                                      └─触发─► Alertmanager(分组/静默/通知:钉钉/邮件)
```

kube-prometheus-stack(Helm Chart)自带:
- Prometheus Operator:以"K8s 资源"方式管理 Prometheus 实例
- **ServiceMonitor**:声明"抓哪些 Service 的指标"(打标 `monitor: true` 即可)
- node-exporter:节点指标;kube-state-metrics:K8s 对象状态指标
- Grafana + 预置仪表盘

## 16.3 K8s 日志体系

- 容器 stdout/stderr → 容器运行时(containerd)落盘 `/var/log/pods/...` → `kubectl logs` 读取
- `kubectl logs -f --tail=100` / `--since=1h` / `--previous`
- 集中采集主流:DaemonSet 方式部署 Promtail/Fluent Bit/Filebeat → Loki/ES
- 排错神器 **stern**:`stern -n prod nginx` 同时盯多个 Pod 的日志(建议装)

## 实验列表

### 步骤 0:安装 Helm(若第 17 章还没装)

```bash
curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
helm version
```

### 实验 1:部署 kube-prometheus-stack

```bash
cd /mnt/d/k8s/16-监控与日志/manifests
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm install kps prometheus-community/kube-prometheus-stack -n monitoring --create-namespace -f kube-prom-stack-values.yaml
kubectl -n monitoring wait --for=condition=ready pod -l release=kps --timeout=600s
kubectl get pods -n monitoring       # prometheus / grafana / alertmanager / exporter 全家桶
```

### 实验 2:访问 Grafana

```bash
kubectl port-forward -n monitoring svc/kps-grafana 3000:80 --address 0.0.0.0 &
# Windows 浏览器打开 http://localhost:3000
# 默认账号 admin / prom-operator(在 values 里可改)
```

推荐 Dashboard(左侧 Dashboards → Import 输入 ID):

| ID | 名称 | 看什么 |
|----|------|--------|
| 315 | Kubernetes Cluster Overview | 集群总览 |
| 1860 | Node Exporter Full | 节点 CPU/内存/磁盘 |
| 8588 | Kubernetes Deployment/CPU/Memory | 工作负载资源 |
| 747 | Kubernetes Pods | Pod 视角 |

### 实验 3:造点指标与日志

```bash
kubectl apply -f lab01-log-generator.yaml
kubectl logs -f deploy/log-app -n mon-lab
# Prometheus 查询(PromQL,9090 端口 port-forward 后在 Web UI 试):
#   rate(container_cpu_usage_seconds_total{namespace="mon-lab"}[1m])
kubectl port-forward -n monitoring svc/kps-kube-prometheus-stack-prometheus 9090:9090 &
```

### 实验 4:自定义告警规则(PrometheusRule)

```bash
# 先阅读规则文件,再应用(示例:Pod 重启次数告警)
kubectl apply -f prometheus-rule-example.yaml
kubectl get prometheusrule -n monitoring
# Prometheus Web → Alerts 页签应出现新规则
```

### 实验 5:stern 多 Pod 日志(可选工具)

```bash
# 安装:https://github.com/stern/stern/releases(下载 linux-amd64 放 /usr/local/bin)
stern -n monitoring 'kps.*' --tail 5
```

### 清理

```bash
helm uninstall kps -n monitoring && kubectl delete ns monitoring
kubectl delete ns mon-lab
```

## 常见问题

| 问题 | 答案 |
|------|------|
| Grafana 打不开? | port-forward 是否存活;WSL2 需确认 Windows→WSL 的 localhost 转发 |
| ServiceMonitor 没抓到数据? | Service 要有 `monitor: true` 标签(与 values 的 selector 对上)+ 服务有 /metrics |
| 内存吃紧? | values 里已把持久化和副本调低;再紧张就只装 metrics-server(第 15 章) |
| 日志去哪了? | `docker exec k8s-learning-worker ls /var/log/pods/`(节点容器里看落盘) |
